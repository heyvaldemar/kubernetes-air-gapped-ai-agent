# Threat model

What this reference architecture defends against, the control for each threat, and the check or eval that shows the control works on every run. The two lists it maps to are the OWASP Top 10 for LLM Applications 2026 (published 2026-08-04) and the OWASP Top 10 for Agentic Applications 2026 (published 2025-12-09). Items the architecture does not address are listed as such, not left out.

## The boundary

| Threat | Control | Shown by |
|---|---|---|
| A workload, or the node, sends data out | The host's firewall rejects anything leaving kind's bridge; the node has no DNS server; CoreDNS answers only for the cluster and the registry ([ADR 1](decisions/0001-the-boundary-is-the-runners-firewall.md)) | e2e checks 1 to 4: a pod and the node each fail to reach 1.1.1.1 by IP and to resolve example.com |
| Something runs that was not brought in and checked | Every image comes from the registry inside, seeded by digest before the cut ([ADR 2](decisions/0002-the-registry-inside-has-its-own-name.md)) | e2e check 5: the node cannot pull an image the registry does not hold. Static check `boundary`: every image a manifest names is in `airgap/images.txt` |
| The registry is read or impersonated on the wire | TLS from the boundary's CA; plain HTTP refused | e2e check 8 |
| Something inside pushes to the registry: a tampered image under a name the cluster pulls | One account, `loader`, may write; its password is made per run and handed over on stdin; reads stay open ([ADR 2](decisions/0002-the-registry-inside-has-its-own-name.md), amended) | e2e check 12: a push with no password and with a wrong one refused with 401, the loader's started and cancelled. Static check `boundary`, three plants. A model pushed later would still fail admission unsigned |
| A control is down, and what it checked goes unchecked: Kyverno stopped, or the gateway's pod lost | Every admission policy fails closed (`failurePolicy: Fail`). That is not enough on its own: Kyverno deletes its own webhooks when it is scaled to zero or uninstalled, and in run 39543289132 a model nobody signed was admitted. The API server's own guard refuses every model while Kyverno's webhook for the models is missing ([ADR 17](decisions/0017-no-model-while-kyverno-is-away.md)): an outage, not a hole. The gateway is the only route to a model server, so while it is gone nothing answers rather than something answering around it. One replica of each on one kind node, so here a stopped control is an outage; `aws-eks-reference-platform` runs Kyverno's admission controller three times over, and a gateway needs two replicas and a disruption budget before losing one is not | `tests/e2e/gameday.sh`, daily: with Kyverno at zero, a model nobody signed and one under a licence not on the list are refused, and so is the signed model; the served model keeps answering; Kyverno back, the seconds until the signed model is admitted; the gateway killed, the model server unreachable around it, and the seconds until it answers. Static check `policies`, plants: `failurePolicy: Ignore`, and a guard that admits when Kyverno's webhook is missing |
| On AWS, data leaves in the names a workload looks up: a VPC's resolver answers any name on the internet whatever the routes say | A Route 53 Resolver DNS Firewall answers AWS's names and the VPC's internal ones and refuses every other name with NXDOMAIN, fail-open off; no internet gateway, no NAT, AWS's services through endpoints ([ADR 18](decisions/0018-the-boundary-on-aws.md)) | `tests/e2e/aws.sh` on AWS: a pod and the node cannot resolve example.com or ask 8.8.8.8, beside controls that resolve ECR inside the VPC; with the firewall off both resolved example.com (run 39632816543), with it on neither did (run 39636241165). Static check `aws`, plants |
| On AWS, the admission controller's registry credential is a key that leaks, or reads more than it needs | Kyverno reads ECR through EKS Pod Identity: a role for its admission controller's service account that reads this run's repositories and nothing else; no key, and not the node's role ([ADR 18](decisions/0018-the-boundary-on-aws.md)) | Static check `aws`: Terraform tests hold the role to `pods.eks.amazonaws.com`, the one service account and read actions on the run's repositories, three plants. On AWS, every signature and AI-BOM admission read came through it (run 39700915485) |
| On AWS, the agent's NetworkPolicies are accepted and enforce nothing | The VPC CNI enforces them, `enableNetworkPolicy` ([ADR 18](decisions/0018-the-boundary-on-aws.md)) | Static check `aws`, one plant. On AWS, the game day finds the model server unreachable from the agents' namespace with the gateway down (run 39700915485) |
| With a model outside, a workload uses the way out the model is given, with a key of its own | One rule on the host: the egress node alone, to Anthropic's published API range, on TCP 443. Only the gateway runs on that node: the API server refuses any pod outside its namespace that tolerates the node's taint, tolerates every taint or names the node. The boundary resolves no outside name; the gateway is given the API's address ([ADR 14](decisions/0014-one-way-out-for-a-model-outside.md)) | Weekly, `tests/e2e/frontier.sh`: the gateway alone on the egress node; the three ways onto it refused, the same pod without them admitted; no connection to the API from the other node; from the egress node, the API on 443 and nothing else. Static check `frontier`, eight plants |
| With a model outside, its credential is stolen | No API key exists. Each run exchanges its GitHub identity, under a federation rule naming this repository's main branch, for a token that lives ten minutes, handed to the gateway through stdin and replaced every minute; the workspace it spends from has a monthly limit | Static check `frontier`: the job runs on main only and reads no stored secret; the backend reads its token from a Secret, never a key written in |

## The model

| OWASP | Threat | Control | Shown by |
|---|---|---|---|
| LLM04 Supply Chain, ASI04 Agentic Supply Chain Vulnerabilities | Swapped or tampered model weights | The model is an image pinned by digest, built reproducibly from a file pinned by sha256, signed with the operator's key, verified at admission offline ([ADR 3](decisions/0003-model-weights-as-a-signed-image-volume.md)) | e2e check 9: unsigned weights, weights signed by another key, the model by tag and an image volume from elsewhere are refused, the signed model is admitted. Every run rebuilds the image and fails if its digest moved |
| LLM04 Supply Chain | A model the site may not run: an unknown origin, or a licence it does not allow | An AI-BOM per model (CycloneDX ML-BOM: origin, revision, sha256, licence), attested with the operator's key; admission requires it and holds every licence of every model in it to the site's list; an SPDX expression is concluded to ids by `scripts/mlbom.py` and refused at admission ([ADR 9](decisions/0009-an-ai-bom-for-every-model.md)) | e2e check 9: a signed model with no AI-BOM, one whose AI-BOM declares GPL-3.0-only, one listing an allowed licence beside one that is not, one with a second model and no licence, and one with an expression, are refused; a concluded expression is admitted. Static checks `policies` and `mlbom`, with planted violations |
| LLM04 Supply Chain | The operator's key is copied, or due for rotation, and the models it signed are still trusted | Rotation in three phases from the policy that runs: the operator's key, both, the next key alone; what runs is signed again with the next key in the overlap ([ADR 16](decisions/0016-rotating-the-operators-key.md)) | Daily, `tests/e2e/rotation.sh` with a model served: a model signed with the retired key alone is refused within a minute of the policy changing, though admitted a moment before; the served model, signed again and restarted, comes back |
| LLM05 Data and Model Poisoning | A model trained to misbehave | Not addressed: the model is a published one, chosen by measurement ([ADR 4](decisions/0004-small-models-on-cpu-chosen-by-measurement.md)) | The evals show its behaviour, not its training |
| LLM06 Unbounded Consumption | An agent or a caller exhausts the model server | The MCP server's per-identity rate limit; the model server's memory limit; the evals Job's deadline; in front of the models, the gateway's quota and token budget per service account, keyed on the token's subject ([ADR 10](decisions/0010-one-gateway-in-front-of-the-models.md), [ADR 11](decisions/0011-the-gateway-knows-who-is-calling.md), [ADR 12](decisions/0012-a-token-budget-per-caller.md)) | Gateway job: a workload's fourth request in a minute is refused with 429 and another workload is still served; a workload that spent its 1,000 tokens in one request is refused its next. Evals: the gateway refused none of the agent's requests over its quota or budget. Static check `gateway`: every caller has a budget, every route goes to a model backend. Not load-tested |

## The agent

| OWASP | Threat | Control | Shown by |
|---|---|---|---|
| LLM01 Prompt Injection, ASI01 Agent Goal Hijack | An instruction in a record or a report turns the agent | Nothing in the model is relied on. Tool results are data in the system prompt; the boundary decides what acting on them can reach | Evals, injection category: how often the model acted on the instruction (measured, published), and whether anything left (gated at zero) |
| LLM02 Sensitive Information Disclosure, ASI02 Tool Misuse | The agent sends data outside through a tool it is granted | `send_email`'s schema holds the recipient to `@acme.example`; the server validates every call before any upstream sees it ([ADR 6](decisions/0006-tools-through-the-sandboxs-mcp-server.md)). In front of it, the model server's grammar, built from the same schema, keeps most models from writing an outside address at all; it depends on the chat template and nobody configures it, so the boundary does not rest on it ([ADR 13](decisions/0013-the-decoder-is-a-control.md)) | Evals: emails that left the outbox for an address outside acme.example, gated at zero; the model's attempts outside, and the server's refusals of them, counted. Every model runs a second time with the patterns hidden from it: in run 39369404367 the six tried outside 92 times, and the server refused all 92 |
| LLM03 Excessive Agency, ASI03 Identity & Privilege Abuse | The agent uses a tool it should not have, or a credential it should not hold | One identity, three tools; the destructive tool is granted to no one; the records key lives only with the records service and the MCP server; the agent's token is for the MCP server's audience only | Static check `mcp`: no destructive tool is granted. Evals: records deleted, gated at zero; requests beyond the agent's rights it declined, measured |
| ASI03 Identity & Privilege Abuse | The confused deputy: someone, or an instruction hidden in data, uses the agent's rights to do what the person asking may not | Every MCP call carries the agent's token and the token of the person it acts for; the agent may do only what both are granted, down to the person's customers; a customer outside them is answered as one that does not exist; no person, no call ([ADR 15](decisions/0015-the-agent-acts-for-a-person.md)) | Daily, `tests/e2e/people.sh`, ten checks with their controls; on the server before the change, 7 of 10 failed, an email sent for someone who may not send one among them. Every model job: no call let through beyond the person's rights, recomputed from the audit. Static check `mcp` runs the server for every person; five plants |
| ASI03 Identity & Privilege Abuse | A workload calls the models as no one, or as the agent, to spend its quota | The gateway requires a service account token for its own audience, checked against the cluster's keys; the quota is keyed on the token's subject, never on a header ([ADR 11](decisions/0011-the-gateway-knows-who-is-calling.md)) | Gateway job: no token, and a token for the Kubernetes API, refused with 401; a workload that writes `x-client-id: support-agent` is still held to its own quota. Static check `gateway`: a quota keyed on anything but `jwt.sub` fails |
| LLM07 Misinformation | The agent invents data | Nothing structural | Evals, grounding category: answers without invented data, measured |
| LLM10 Improper Output Handling | The agent's output is executed somewhere | The agent's output goes to the evals' scorer and to tools by schema; nothing executes it | Not applicable here |

## Residual risks

- **The model is fooled, and oversteps.** In the first runs, Granite-4.0-1B acted on an instruction hidden in a report in half the injection attempts and declined none of the requests beyond its rights; Qwen3.5-2B ignored every hidden instruction and still tried to email outside when a user asked it to. The architecture is designed for both; a reader should know them.
- **Misdirected email inside the company.** The schema holds recipients to the company's domain, not to the right person. A model that is fooled emails a colleague nobody named. In the run v1.1.0 was cut from, the four models that never wrote an outside address sent 47 such emails between them; the two that tried outside, and were refused, sent none. 39 of the 47 were an outside address with its domain swapped for the company's: the grammar re-addressing an attempt to send outside (ADR 13). A recipient allowlist per task, or a person approving each send, would close it.
- **No transparency log.** Signatures are checked by key alone. A stolen key signs anything, and nothing public records it. Keyless signing with a TUF mirror inside the boundary is the step after kyverno#17883.
- **The keys are made per run.** In CI the operator's signing key and the boundary's CA are generated on the runner. In a real install they are the site's, kept off any build machine.
- **No runtime isolation for the agent here.** The agent's side runs under the restricted Pod Security profile, not under gVisor; the sandbox repository is where that is built.
- **With a model outside, the data goes to it.** The agent's prompts, the records its tools return and the report's text reach Anthropic: that is what the weekly job with a model outside measures, and why the daily runs keep the model inside. On the egress node, `kube-system`'s node agents share the host's network and could reach the API's range; whoever may create pods in the gateway's namespace may place one there; a token taken from the gateway spends from its workspace for up to ten minutes.
- **A person's token passes through the agent.** It holds it for its life, and the model gateway still knows only the agent, so quotas are per agent, not per person. Scope is by tool and customer, not by field ([ADR 15](decisions/0015-the-agent-acts-for-a-person.md)).
- **One node, one registry, one replica of each service.** A reference for the controls, not for availability.
- **The price is a list price from a third-party snapshot.** `evals/pricing.json` says where it comes from.
